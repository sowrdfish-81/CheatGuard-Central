# CheatGuard Central v1.9.8

## Session start reliability (mobile hotspot fix)

- A start that never completes (slow machine, a UAC prompt answered late, or a
  stalled verification on a mobile hotspot) now rolls the lockdown back fully.
  Previously the PC could be left with a dead DNS resolver - "Wi-Fi connected,
  no Internet" - after a failed start; that can no longer happen.
- The elevated helper writes a timestamped step log to
  `C:\ProgramData\CheatGuard\network\helper-log.txt`, so a failed start shows
  exactly which stage it reached instead of a generic timeout.
- The Windows UAC approval window grew from 20 to 90 seconds and the
  helper-start window from 90 to 150 seconds; both are followed by the same
  rollback when they still time out.
- The failure dialog now states that the rollback already ran (Internet and
  files keep working) and names the helper log for support.

## Data safety

- Changing the administrator password now re-seals every saved session vault
  with the new password first. Before this, all previously sealed logs became
  permanently unreadable after a password change, with no warning.
- Deleting an exam profile asks for confirmation.

## Monitoring

- The central monitor CSV no longer writes a duplicate header row each time
  the monitor is started on the same day.
- The exam-code field and the New-code button lock while a monitor is running
  (the running session keeps authenticating against the code it started with).

## Student setup

- The exam code is validated on the setup card (3-12 letters or numbers) and
  an invigilator IP that does not look like an address asks for confirmation,
  instead of silently joining nothing.
- When the invigilator's monitor PC cannot be reached, one row is recorded in
  the sealed session log naming the unreachable IP, so missing alerts are
  explainable afterwards.

## Updater

- A downloaded update whose installer fails to launch now shows an error with
  the installer's location instead of failing silently.
