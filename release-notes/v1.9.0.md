# CheatGuard Central v1.9.0

## Highlights

- **Encrypted central-monitor transport.** Student-to-invigilator event
  traffic now travels over TLS 1.2/1.3 by default with full certificate
  validation (PKCS12 keystore on the monitor PC, truststore on student PCs,
  SAN check of the typed address). The HMAC challenge-response exam-code
  proof remains as a second layer on the encrypted channel. Plaintext TCP is
  a development-only opt-in with a visible warning, and both ends refuse to
  fall back silently. Port unchanged (TCP 47821); same firewall rule.
- **Automatic encrypted vault backups.** Every sealed session vault (+ its
  signature) is copied atomically to
  `%ProgramData%\CheatGuard\vault-backup\`. Plaintext logs are never backed
  up. Retention: newest 30 backups / 90 days by default, both configurable
  (`backup.retention.count`, `backup.retention.days`). Interrupted copies
  self-heal; failures are logged, never fatal; the active vault is never
  touched.
- **Diagnostic log rotation.** `AppLog` day files now roll by size
  (`cheatguard-YYYY-MM-DD.1.log`... , 5 MiB default) in addition to the
  14-day age prune. Audit vaults and diagnostics remain strictly separate.

## Repository / engineering

- GitHub Actions CI: compile, run all five headless test suites, PowerShell
  syntax validation, `git diff --check`, automatic WiX 3.14 download,
  installer build with checksum generation and verification, artifact upload.
- Automated releases on `v*` tags with optional SHA-256 Authenticode signing
  (RFC 3161 timestamping; certificate exists only in the runner's temp folder
  and is deleted in a `finally` block; signing is cleanly skipped and
  reported when secrets are absent).
- Manual Windows-VM integration workflow (`integration-vm.yml`) driving the
  new `test/integration/` harness: silent install/uninstall, app startup,
  real lockdown arm/restore cycle, emergency restore. Runs only on a labeled
  disposable VM runner and refuses to run on a workstation.
- Branch protection on `main`: PRs required, 1 approval, CI checks required,
  up-to-date branches, no force pushes, no deletion.
- Project documentation: LICENSE (MIT), CONTRIBUTING.md, SECURITY.md,
  CODE_OF_CONDUCT.md, issue/PR templates, `docs/CENTRAL_TLS.md`,
  `docs/BACKUPS_AND_LOGS.md`. Historical one-off test scripts and captured
  output removed from `test/`.

## Notes for invigilators

- Before the first monitored exam, generate the monitor TLS material once on
  the invigilator PC:
  `support\generate-central-tls.ps1 -LanIp <your-LAN-IP>` (run as
  Administrator), then copy `central-monitor-truststore.p12` to every student
  PC. Password goes in the `CHEATGUARD_CENTRAL_TLS_STOREPASS` environment
  variable or the app config - never on a command line. Details:
  `docs/CENTRAL_TLS.md`.
- If a monitor PC cannot present a valid keystore, the monitor refuses to
  start with a precise error - it will not silently downgrade to plaintext.

## Checksums

`CheatGuardCentral-Setup.exe.sha256` is attached to this release; the
in-app updater verifies it before installing. The installer is unsigned
unless the release workflow reported signing as performed (see the release
workflow run log).
