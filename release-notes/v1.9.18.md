# CheatGuard Central v1.9.18

A full code-review pass over the whole codebase: fixes a broken central-monitor
link, DNS resolver correctness bugs, audit-log data loss, dead enforcement
paths, and several hangs and false alarms that could disrupt a live exam.

## Central monitor

- **The student → invigilator feed never worked in TLS mode.** The reporter
  connected an already-connected TLS socket and threw on every attempt; events
  now flow over the production TLS transport. (This is the headline fix.)
- Student ID / course code / hostname are now sanitized in the event protocol,
  so a `@@@` or newline in them can no longer corrupt the event framing or the
  challenge-response handshake.
- Stopping the reporter now closes the connection so a sender blocked waiting
  for the challenge actually exits (plaintext dev mode).
- The invigilator's **Mark: cheat confirmed / Mark: cleared** buttons were
  dead — no listeners were attached, so the whole verdict workflow (and the
  CHEAT CONFIRMED ranking) was unreachable. They work now.
- The persistent inbound firewall rule for the monitor is removed by a shutdown
  hook if the app exits while the monitor is running.
- The student table no longer races client-reader threads when opening a
  student's detail view.
- CSV export neutralizes spreadsheet formula injection from unauthenticated
  event fields.

## DNS allowlist server

- Fixed a QTYPE off-by-one that read the type one byte early: every common
  query type collapsed to type 0, so A and AAAA shared one cache entry (wrong
  record family served) and the reply validation's type check was ineffective.
- A truncated upstream reply could throw out of the answer parser; it is now
  bounded and skipped safely.

## Sessions and audit logs

- Sealing a log named `SESSION.DAT` (uppercase extension) derived the vault
  name case-sensitively, encrypted the file onto itself and then deleted it —
  the session evidence was destroyed. Vault names are now derived
  case-insensitively with a canonical-path guard.
- A legitimately empty sealed log could never be opened again (off-by-one in
  the GCM vault length check).
- Deleting a protected log via the elevated path never worked: the nested
  PowerShell quoting was broken, so the elevated step always failed. The inner
  script now travels base64-encoded and its exit code is checked.
- The protect-request handoff to the elevated helper is written atomically and
  rejects stale done-files, so hardening can no longer be "confirmed" without
  happening.
- A failed device scan no longer erases the device baseline (which had reported
  every already-present USB device as newly attached on the next scan).

## Enforcement

- One transient `taskkill` failure no longer exempts an unauthorized app from
  termination for the rest of the session; kills are retried every cycle while
  only the log line stays deduplicated.
- A URL in a window title (the `s:` of `https://...`) no longer matches the
  drive-path rule, so allowed apps showing a link are not falsely closed.
- A title showing the exam folder path itself (no trailing separator) is clean;
  sibling folders (`Exam_1-backup`, `Exam_10`) are still flagged.

## Reliability

- Every child-process read now waits with a timeout before reading output
  (monitor LAN IP, `where`, shortcut resolution, app-name lookup, upstream DNS
  probe, foreground-window probe, `taskkill`), so a hung helper can no longer
  freeze the watchdog loop or the UI thread indefinitely.
- The elapsed-session clock no longer freezes after minimize-to-tray.
- The auto-updater re-checks for an active session when the download completes
  and refuses to exit mid-exam (it did before, killing the lockdown).
- The elevated self-relaunch quotes paths itself, so a Windows profile path
  with a space no longer anchors the exam folder to the wrong account.
- A corrupt config/profile file (malformed unicode escape) falls back to
  defaults instead of crashing startup; internationalized (punycode) domains
  can be allow-listed again.
- Auto-provisioned TLS truststore now uses the managed store password, so the
  loopback dry-run on the invigilator's own PC works.
- The student shortcut quotes its exam-folder argument, so folders with spaces
  open correctly in VS Code / Eclipse.
- `support\diagnostics.bat` and `support\emergency-restore.bat` also resolve
  their scripts when run from the repository layout, not only when installed.
